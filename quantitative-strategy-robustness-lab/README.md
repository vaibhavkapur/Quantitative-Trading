# Quantitative Strategy Robustness Lab

Offline research and validation toolkit for evaluating whether candidate quantitative trading strategy results survive **multiple testing**, **transaction costs**, **out-of-sample walk-forward evaluation**, **block bootstrap uncertainty**, **parameter perturbations**, and **cherry-picking / ledger integrity audits**.

> **Scope & Limitations Notice:** This is an independently developed offline educational and research prototype. Statistical diagnostics (DSR, CSCV PBO, block bootstrap, walk-forward, perturbation analysis) assess historical consistency under explicit stationarity and dependence assumptions—they **do not prove future returns**. Live capital, real brokerage integrations, customer records, credentials, and proprietary employer/SAAT artifacts are excluded.

## Core Capabilities

- **Immutable Experiment Registry (`src/robustness_lab/registry.py`)**: Append-only SHA-256 hash-chained JSONL trial ledger recording **all** attempted configurations (`COMPLETED`, `FAILED`, `REJECTED`, `ABORTED`) with mandatory `failure_reason` strings and tamper detection.
- **Multiple-Testing Diagnostics (`statistics.py`, `pbo.py`)**:
  - Probabilistic Sharpe Ratio (PSR) and Deflated Sharpe Ratio (DSR) with Mertens (2002) skewness/Pearson-kurtosis standard errors, Lo (2002) Bartlett-weighted autocorrelation variance inflation, and eigenvalue participation-ratio effective trial count ($N_{\text{eff}}$).
  - Probability of Backtest Overfitting (PBO) via Combinatorially Symmetric Cross-Validation (CSCV, Bailey et al. 2015) with OOS rank logits, OOS loss probability, and IS-to-OOS degradation slope.
- **Perturbation, Uncertainty & OOS Suite (`bootstrap.py`, `walk_forward.py`, `perturbation.py`, `costs.py`)**:
  - Stationary & circular block bootstrap confidence intervals for Sharpe, mean return, and max drawdown.
  - Expanding and rolling purged walk-forward evaluation with strict training-window selection, transaction/borrow cost modeling, and simple benchmark comparison.
  - Local parameter-grid neighborhood stability and Sharpe cliff detection.
- **Integrity & Promotion Gating (`integrity.py`, `promotion.py`, `reporting.py`)**:
  - Sequence-gap, return-hash, exact/near-duplicate, and parameter-grid coverage checks for cherry-picking detection.
  - Fail-closed promotion gate (`PROMOTE`, `HOLD_FOR_REVIEW`, `REJECT`) that **always rejects** when required evidence is incomplete or registry integrity fails.
  - Versioned machine-readable JSON + reviewed Markdown reports with deterministic `run_id` and replay verification.

## Quickstart

From `quantitative-strategy-robustness-lab/`:

```bash
# 1. Create virtual environment and install pinned dependencies
python3 -m uv venv .venv --python 3.12
python3 -m uv pip install --python .venv/bin/python -r requirements.lock
python3 -m uv pip install --python .venv/bin/python --no-deps --no-build-isolation -e .

# 2. Run the full reproducible validation pipeline (fixtures + pytest + demo + CLI replay)
bash scripts/ci_check.sh
```

Individual CLI commands (after editable install):

```bash
# Verify immutable ledger integrity
.venv/bin/robustness-lab verify-registry \
  --ledger data/fixtures/valid/known_signal_experiment/registry.jsonl

# Evaluate an experiment directory and emit JSON + Markdown reports
.venv/bin/robustness-lab --verbose evaluate \
  --experiment-dir data/fixtures/valid/known_signal_experiment \
  --policy config/default_policy.json \
  --output-dir reports/baseline \
  --report-name known_signal

# Deterministically replay and verify logical equality against baseline JSON
.venv/bin/robustness-lab replay \
  --experiment-dir data/fixtures/valid/known_signal_experiment \
  --policy config/default_policy.json \
  --baseline-report reports/baseline/known_signal.json
```

## Methodology Assumptions & Known Limitations

- **Stationarity:** DSR, CSCV PBO, and block bootstrap assume approximate weak stationarity over the evaluation window; structural macro regime breaks are not modeled.
- **Asymptotic Sharpe SE:** PSR/DSR uses Mertens (2002) higher-moment and Lo (2002) Bartlett autocorrelation corrections; severe fat tails (flagged by `diagnose_outliers`) degrade normal-tail accuracy.
- **Effective Trial Estimation:** Eigenvalue participation ratio $N_{\text{eff}} = N^2 / \text{tr}(C^2)$ relies on sample correlation matrices, which are noisy when $N$ approaches $T$.
- **Single-Writer Ledger:** The JSONL hash-chained registry targets offline research runs; concurrent multi-writer distributed sweeps are untested and out of scope.
- **Untested / Out-of-Scope Capabilities:** Real historical market feeds, live order execution, multi-process database ledgers, and runtime cross-imports from sibling projects (sibling projects are independent standalone packages at the repository root; see `docs/integration.md`).
